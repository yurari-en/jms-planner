# 画面共有によるステータス自動入力(第1段階)設計書

作成: 2026-10-12 / 状態: レビュー待ち / 対象: `jms-planner-kit`

## 1. 目的と背景

キャラクターのステータス(最終値・%合計・%未適用値・攻撃力/魔力・ダメージ%・ボス%・クリダメ%・Lv・戦闘力)を手で写す手間をなくす。
ユーザーの要望は「ブラウザの画面共有でゲームウィンドウを映し、ゲーム内で項目にカーソルを合わせるだけで入力される」こと。
参考に挙げられた kinokohub.net「画面から自動入力」は、画面共有 + OpenCV.js のテンプレート照合で UI の位置と倍率を特定し、
ゲームフォント専用に学習した小さな文字認識モデルで数値を読む構成だった(2026-10-12 に公開コードを確認)。

本機能は DESIGN.md §0.2 の F1〜F5 の外側に追加する新機能(F6「画面読み取り」)である。実装は本設計書の承認後に行う。

### 1.1 スパイクの結論(2026-10-12)

- 汎用 OCR は不採用。Tesseract.js(日本語)はステータス画面の数値をほぼ読めず(1/23)、Windows 標準 OCR は精度が高い(約 20/23)がブラウザから使えない。
- ゲームの文字は固定のビットマップフォントなので、**文字テンプレート照合**(数字・記号・限られたラベル)で高精度に読める。依存ライブラリも学習データも不要。
- ゲーム内ツールチップの「基本数値 / %数値 / ※未適用」は、本アプリの `StatInput { final, pct, nonPct }` と一対一に対応する。

## 2. スコープ

### 2.1 第1段階(本書)で読み取る項目

| 読み取り元 | 項目 | 反映先(`CharacterInput`) |
|---|---|---|
| キャラ情報ウィンドウ上部 | Lv | `level` |
| STAT 欄 | 戦闘力(例: `1億 1809万 719`) | `displayedCP` |
| STAT 欄 | STR / DEX / INT / LUK の最終値 | `stats[X].final` |
| STAT 欄 | 攻撃力 または 魔力(職業の `attackType` に従う) | `attack.final` |
| STAT 欄「詳細」 | ダメージ、ボスモンスターダメージ、クリティカルダメージ | `dmgPct`, `bossPct`, `critDmgPct` |
| 各ステにカーソルを合わせた時のツールチップ | `[適用中の数値]` の 基本数値 と %数値、`[基本数値]` 内訳のうち「※」付き(掛け算から除外)の行 | `stats[X].pct` = %数値、`stats[X].nonPct` = ※行の合計 |
| 攻撃力/魔力のツールチップ | 同上 | `attack.pct` |

主ステ・副ステ以外のステ(例: 戦士の INT)は読まない。デーモンアヴェンジャーの HP(純HP/追加HP)は第1段階では対象外(ツールチップの構成が未確認のため)。

### 2.2 対象外(第2段階以降、または恒久的に対象外)

- 装備ツールチップ(装備の特定、★、潜在、アディ、炎)— 第2段階。アイコン照合(同梱の 4,000 枚超の装備アイコン)、★のピクセル計数、潜在行のラベル辞書を使う想定。
- 職業の自動判定 — ユーザーが既に選択している値を使う。ヘッダーの職業名は照合しない。
- 画像ファイルのアップロード/貼り付けによる読み取り — 画面共有と同じ処理系で実現できるので、第1段階の受け入れ後に小さな追加として検討。
- スマートフォン、フルスクリーン(排他)モードのゲーム画面。

## 3. 前提

- PC 版 Chrome / Edge(`navigator.mediaDevices.getDisplayMedia` でウィンドウ共有ができること)。Firefox は動作確認対象外。
- ゲームはウィンドウモードまたはボーダーレス。画面共有の映像はゲームの実ピクセルで届く(ブラウザが縮小した場合も、UI 倍率検出で吸収する)。
- 入力の自動化はしない(キー・マウス操作のシミュレーションなし)。画面を「見る」だけなので、ゲーム側の保護機構と衝突しない。
- 映像・画像はブラウザ内で処理し、外部へ送らない。保存もしない(読み取り結果の数値だけを localStorage のキャラデータに反映する)。
- ランタイムの外部リクエスト禁止(PROMPT.md)— テンプレート画像とレイアウト定義は `public/` に同梱し同一オリジンから読む。

## 4. UX フロー

1. 入力タブ「ステータス」セクションの右上に **「画面から読み取る」** ボタンを置く。
2. 押すとダイアログが開く。
   - 説明: 「ゲームのウィンドウを共有し、キャラ情報(STAT)を開いたままにしてください。STR/DEX/INT/LUK と 攻撃力(魔力)にカーソルを合わせ、ツールチップが出たら 1 秒ほど待ってください(順不同)。」
   - 注意: 「映像は外部に送られず、ブラウザ内だけで処理されます。」
   - **「共有を開始」** ボタン → ブラウザのウィンドウ選択。開始後はプレビュー(縮小)と、読み取り状況の一覧を表示する。
3. 読み取り状況は項目ごとのチェックリスト。読めた項目は値を表示し、未読は「未検出」。ツールチップ系は「STR のツールチップ: 未検出 → カーソルを STR に合わせてください」のように案内する。
4. 下部に **「反映する」**(1 項目でも読めていれば有効)と「共有を終了」。反映前に差分表を出す(項目 / 現在の値 / 読み取り値)。各行にチェックボックスがあり、外した行は反映しない。
5. 反映は `updateCharacter` 1 回で行い、ステータスの「その他 (アビリティ等)」の保存値 `pctOther[X]` は、読み取った pct から装備由来の自動集計を引いた値に更新する(既存の表示ロジックと整合させる)。
6. 失敗時の文言: 共有の拒否「画面共有が許可されませんでした」、非対応ブラウザ「このブラウザは画面共有に対応していません(PC 版 Chrome / Edge をお使いください)」、ウィンドウ未検出(10 秒)「キャラ情報ウィンドウが見つかりません。STAT を開いているか、UI が隠れていないか確認してください」。

## 5. アーキテクチャ

```
src/capture/
  capture.ts        getDisplayMedia → <video> → OffscreenCanvas。4 fps で ImageData を Worker に送る
  worker/recognize.worker.ts   フレーム解析(下記 locate / fields / glyph / parse を Worker 内で実行)
  locate.ts         アンカー照合: キャラ情報ウィンドウの位置と UI 倍率の検出
  layout.ts         レイアウト定義(public/capture/layout.json の型とアクセサ)
  glyph.ts          文字テンプレート照合(正規化相互相関)。数字・記号・ラベル
  parse.ts          文字列 → 数値(「1億 1809万 719」「74.00%」「2,735」)、ツールチップ行の解釈
  apply.ts          読み取り結果 → CharacterInput の差分(純粋関数)
src/components/input/CaptureDialog.tsx   UI
public/capture/
  layout.json       アンカー・各フィールドの相対座標(倍率 1.0 基準)、ラベル一覧
  templates/*.png   文字・ラベルのテンプレート(倍率 1.0 基準のスプライト)
scripts/build-capture-templates.mjs      サンプル画像からテンプレートを切り出す開発用スクリプト
```

- 重い処理(照合)は Worker で行う(DESIGN.md §7 の方針と同じ)。メインスレッドは映像のフレーム取得と UI だけ。
- `glyph.ts` と `parse.ts` と `apply.ts` は純粋関数で、Node のテストから画像フィクスチャで検証できる。
- 既存の計算系(`src/domain/`)には手を入れない。反映は `useCharactersStore.updateCharacter` 経由。

## 6. 認識アルゴリズム

### 6.1 アンカーと倍率の検出(`locate.ts`)

1. フレームを縮小(長辺 640px)して、アンカー(「戦闘力」ラベル + 枠の一部など、画面内で一意な領域)のテンプレートを候補倍率(0.5〜2.0、0.05 刻みは粗探索→細探索)で照合する。正規化相互相関(NCC)のスコアが閾値(初期値 0.85)以上なら検出。
2. 検出した位置と倍率を全解像度で再照合して確定する。以後のフレームは前回の位置の近傍だけを探索する(ウィンドウを動かしても追従)。
3. ツールチップはカーソル位置に出るため、別アンカー(「[適用中の数値]」ラベル)をフレーム全体で探す。見つかったら、その左上を原点にツールチップのレイアウトを適用する。

### 6.2 フィールドの切り出し(`layout.json`)

アンカー原点からの相対座標(倍率 1.0 基準)で、各項目の数値領域を定義する。例:

```json
{
  "version": 1,
  "anchors": { "stat": { "template": "anchor-stat.png", "scaleRange": [0.5, 2.0] },
               "tooltip": { "template": "anchor-tooltip.png" } },
  "fields": {
    "level":      { "anchor": "stat", "box": [120, -230, 60, 14], "charset": "digits" },
    "cp":         { "anchor": "stat", "box": [100, 0, 260, 18], "charset": "cp" },
    "STR.final":  { "anchor": "stat", "box": [60, 80, 120, 14], "charset": "number" }
  }
}
```

座標はサンプル画像から開発用スクリプトで求め、ゲームの UI 改変があれば JSON の更新だけで追従できるようにする。

### 6.3 文字テンプレート照合(`glyph.ts`)

- 文字集合: `0-9 , . % / : 億 万 秒 ※ + -` と、必要なラベル(`基本数値` `%数値` `[適用中の数値]` `[基本数値]` `[%数値]` と内訳の項目名)。
- 各領域を二値化(ゲームの文字は白/黄/緑など明色、背景は暗色。輝度しきい値は倍率に依存しない)し、連結成分で文字を左から切り出して、各テンプレート(倍率に合わせて最近傍で拡縮)との NCC が最大のものを採用する。スコアが低い文字は `?` とし、その項目は「読み取り失敗」にする。
- 列の揃っている数値は等幅なので、連結成分の幅で `,` `.` を区別できる。`74.00%` のように小数点と `%` を含む場合は `parse.ts` で解釈する。
- 同じ項目を連続 3 フレーム同じ値で読めたら確定(ちらつき・アニメーション対策)。

### 6.4 ツールチップの解釈(`parse.ts`)

- ツールチップ内で `[適用中の数値]` の直下 2 行から 基本数値 と %数値 を読む。
- `[基本数値]` 以下の行で、行頭に `※` テンプレートが一致した行の数値を合計して `nonPct` とする。
- ツールチップの見出し(STR / DEX / INT / LUK / 攻撃力 / 魔力)をラベルテンプレートで判別し、どのステのツールチップかを決める。
- 検算: `final ≈ floor((基本数値 − nonPct) × (1 + pct/100)) + nonPct` が ±2 以内でなければ「要確認」フラグを付ける(反映はできるが差分表に警告を出す)。※この式は 2026-10-12 のサンプル(魔力: 2923 × 1.86 = 5,436)で確認した範囲の仮定で、※付き項目を含むサンプルで要検証。

### 6.5 反映(`apply.ts`)

- 入力: 現在の `CharacterInput`、読み取り結果 `{ level?, cp?, stats: { STR?: {final?, pct?, nonPct?}, ... }, attack?: {final?, pct?}, dmgPct?, bossPct?, critDmgPct? }`、職業定義(主ステ・副ステ・攻撃種別)。
- 出力: 変更行の一覧(項目名、旧値、新値)と、適用後の `CharacterInput` を返す純粋関数。主ステ・副ステ以外のステは無視する。

## 7. テンプレートとレイアウトの作り方(開発手順)

1. サンプル画像(ユーザー提供。キャラ名などを含むため **リポジトリには入れない**)を `C:\Users\amane\projects\maplestory\samples\capture\` に置く。
2. `scripts/build-capture-templates.mjs` が、サンプルから文字・ラベルのテンプレートを切り出して `public/capture/templates/` と `layout.json` を生成する。切り出し位置は同スクリプト内の座標表(倍率 1.0 基準)で管理する。
3. テスト用フィクスチャは **数値・ラベル領域だけを切り出した小さな PNG**(個人情報を含まない)を `tests/fixtures/capture/` にコミットする。

必要なサンプル(第1段階の着手前にお願いするもの):

- UI 倍率 1.0 のキャラ情報ウィンドウ全体(STAT、詳細を開いた状態)。
- 同じ画面で STR / DEX / INT / LUK / 攻撃力 または 魔力 にそれぞれカーソルを合わせたツールチップ(5 枚)。※付きの行があるもの(シンボル・ユニオンなど)を含めたい。
- 可能なら UI 倍率を変えた同じ画面(1 枚)と、別職業(戦士系)の画面(1 枚)。

## 8. エラー処理と性能

- 共有停止(ユーザーがブラウザ側で停止)を検知してダイアログを「共有が終了しました」状態にする。読み取り済みの値は保持する。
- 解析は 4 fps、1 フレームの解析は Worker で 100 ms 以内を目標(アンカー追従時)。初回のアンカー探索は 1 秒以内。
- Worker が落ちた場合は「読み取り処理でエラーが発生しました」を表示し、再試行ボタンを出す。
- 読み取り値の妥当性: Lv 1〜300、戦闘力 0〜9,999 億、% は 0〜999 などの範囲外は「読み取り失敗」にする。

## 9. テスト

- `glyph.ts`: フィクスチャの数値画像(倍率 1.0 と 1.5)を全桁正しく読む。
- `parse.ts`: 「1億 1809万 719」→ 118090719、「2978万 3449」→ 29783449、「74.00%」→ 74、「0秒 / 5%」→ 5(クールタイム減少は対象外だが誤読しないこと)。
- `apply.ts`: カンナ(INT/LUK・魔力)の読み取り結果が `stats.INT`, `stats.LUK`, `attack` に入り、STR/DEX は変更されないこと。差分行の生成。
- `locate.ts`: 合成画像(フィクスチャを黒背景に貼り、1.0 / 1.25 / 1.5 倍に拡大)でアンカーが見つかり倍率が ±0.05 で当たること。
- UI: Playwright は使わず、既存のヘッドレス Edge スクリプトでダイアログの開閉と非対応時の文言を確認する(画面共有の自動許可は不可のため、`getDisplayMedia` をスタブした検証モードを `?captureStub=1` のような開発時フラグで用意する)。

## 10. 配布・プライバシー・性能予算

- 追加アセット: テンプレート数十枚(合計 100 KB 未満)+ layout.json。外部 CDN は使わない。
- 画面共有の映像はメモリ上だけ。`MediaStream` はダイアログを閉じた時に `track.stop()` する。
- 読み取りコードは動的 import(ボタンを押した時に初めて読み込む)にして、初期表示の Lighthouse 指標を落とさない。

## 11. 未確定事項(実装中にサンプルで確認する)

1. ステータスのツールチップで「※未適用」になる内訳項目の種類(シンボル / ユニオン / HEXA など)。本アプリの `nonPct` の定義(DESIGN.md §5.1)と一致するか。
2. JMS の UI 倍率の選択肢(ゲーム設定)と、画面共有で届く映像の実解像度の関係。
3. 「詳細」を閉じた状態でのダメージ%等の位置(詳細を開いた状態を前提にし、閉じていれば案内する)。
4. ゲームのウィンドウが画面外にはみ出した場合の扱い(見えている部分だけ読む)。

## 12. 第2段階の見通し(装備)

装備ツールチップは要素が多い(装備名、★、潜在 3 行、アディ 3 行、炎、呪文書)。第1段階の基盤(アンカー検出・倍率・文字照合)をそのまま使い、
装備の特定は同梱アイコンとの照合、★は金星/灰星の色の計数、炎は数値の色(黄)で判別、潜在・アディの行は語彙(数十種)のラベルテンプレートで読む。
部位ごとのサンプル(武器・防具・装飾)が必要になる。本書の承認後、第1段階の受け入れが済んでから別の設計書を書く。

## 13. 受け入れ基準

- カンナのサンプル画面(2026-10-12 提供分と追加分)で、Lv・戦闘力・INT/LUK 最終値・魔力・ダメージ%・ボス%・クリダメ%・INT/LUK/魔力のツールチップ(pct, nonPct)が全て正しく読める。
- 共有開始から全項目の読み取りまでの操作が 1 分以内に終わる(カーソルを 5 か所に合わせるだけ)。
- `npm test`・`npm run lint`・`npm run build` が通り、既存の計算結果(テスト 235 件)に影響がない。
- Lighthouse の初期表示指標(Performance 99 / Accessibility 100)を維持する。
